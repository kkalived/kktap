# KK便利贴 (Tapp) - 产品需求文档

## 1. Problem Statement

用户需要一个简单直观的电子便利贴工具，能够在 Windows 桌面上创建、编辑和管理多张便利贴。用户希望便利贴具有真实纸张的视觉效果，支持文字、图片和截图，同时能够堆叠翻页、右键快捷操作，并且数据能够持久保存。

当前市场上缺少既美观又功能完整的 Windows 桌面便利贴应用，用户需要一个无需复杂配置、开箱即用的解决方案。

## 2. Solution

KK便利贴是一款基于 Electron 的 Windows 桌面应用，提供仿真实物便利贴的用户体验。用户可以在屏幕上放置多张便利贴，每张便利贴支持文字编辑和图片展示，便利贴可以堆叠组合并像翻书一样翻页切换。应用提供全局截图快捷键、右键菜单操作、历史记录管理和系统托盘常驻等功能，所有数据自动持久化保存。

## 3. User Stories

### 3.1 便利贴基础操作

1. 作为用户，我希望在屏幕上创建新的便利贴，以便随时记录想法
2. 作为用户，我希望通过拖拽移动便利贴位置，以便将便利贴放在屏幕任意位置
3. 作为用户，我希望通过拖拽边缘或角落调整便利贴大小，以便适应不同内容量
4. 作为用户，我希望点击便利贴即可直接编辑文字，以便快速记录内容
5. 作为用户，我希望输入内容自动保存，以便不用担心数据丢失
6. 作为用户，我希望关闭软件后重新打开时所有便利贴恢复原状，以便下次继续使用
7. 作为用户，我希望点击右上角 X 按钮删除当前便利贴，以便清理不需要的内容

### 3.2 便利贴堆叠与翻页

8. 作为用户，我希望将多张便利贴堆叠在一起，以便组织相关内容
9. 作为用户，我希望点击堆叠中下层便利贴露出的边缘翻页，以便查看堆叠中的其他便利贴
10. 作为用户，我希望便利贴翻页有流畅的3D动画效果，以便获得良好的视觉体验
11. 作为用户，我希望一个堆最多包含3张便利贴，以便控制堆的复杂度
12. 作为用户，我希望拖拽便利贴时自动检测与附近便利贴的合并，以便简化操作
13. 作为用户，我希望将堆中的便利贴拆分出来独立显示，以便灵活管理
14. 作为用户，我希望点击堆叠露出边缘时能收起所有便利贴，以便节省屏幕空间
15. 作为用户，我希望再次操作时能展开收起的便利贴，以便继续使用

### 3.3 图片与截图

16. 作为用户，我希望在便利贴上插入本地图片，以便展示参考资料
17. 作为用户，我希望通过全局快捷键快速截图，以便捕捉屏幕内容

19. 作为用户，我希望截图后自动创建新便利贴显示截图，以便快速保存信息
20. 作为用户，我希望按 Esc 键取消截图操作，以便在选错区域时撤销
21. 作为用户，我希望修改截图快捷键以便适应个人习惯
22. 作为用户，我希望截图时便利贴不出现在截图中，以便获得干净的截图

### 3.4 文字格式化与待办

23. 作为用户，我希望调整文字大小（A+/A-按钮），以便提高可读性
24. 作为用户，我希望将文字加粗或倾斜，以便强调重要内容

### 3.8 日报生成

### 3.9 视觉设计

## 4. Implementation Decisions

### 4.1 技术栈选择

- **框架**: Electron 42 - 跨平台桌面应用框架
- **主进程**: Node.js - 处理窗口管理、文件系统、全局快捷键
- **渲染进程**: 原生 HTML/CSS/JS - 无需额外前端框架，降低复杂度
- **打包工具**: electron-builder - 生成 Windows NSIS 安装包
- **IPC 通信**: contextBridge - 安全的主进程/渲染进程通信方式

### 4.2 模块架构

```
src/main/
├── main.js           # 应用入口，初始化所有管理器
├── preload.js        # contextBridge API 暴露
├── noteStore.js      # 数据持久化，单一数据真相来源
├── windowManager.js   # BrowserWindow 创建、销毁、堆叠合并拆分
├── screenshotService.js  # 截图捕获与裁剪
├── hotkeyManager.js   # 全局快捷键注册
├── trayManager.js     # 系统托盘管理
└── reportService.js   # 日报生成服务

src/renderer/
├── note-stack/       # 便利贴主窗口
├── screenshot-overlay/  # 截图选区覆盖层
├── history/          # 历史记录窗口
└── settings/         # 设置窗口
```

### 4.3 IPC 消息规范

所有渲染进程与主进程通信使用 `window.api.*` 接口：

| 消息频道 | 方向 | 用途 |
|---|---|---|
| `notes:*` | 双向 | 便利贴 CRUD 操作 |
| `stacks:*` | 双向 | 堆叠合并/拆分操作 |
| `screenshot:*` | 双向 | 截图相关操作 |
| `files:*` | 双向 | 文件选择与读取 |
| `settings:*` | 双向 | 设置读写 |
| `reports:*` | 双向 | 日报生成与历史 |
| `window:*` | 双向 | 窗口控制 |

### 4.5 窗口类型

| 窗口 | 特性 |
|---|---|
| 便利贴窗口 | frameless, transparent, alwaysOnTop, resizable, skipTaskbar |
| 截图覆盖层 | frameless, transparent, fullscreen, alwaysOnTop |

### 4.6 安全约束

- `contextIsolation: true` - 渲染进程隔离
- `nodeIntegration: false` - 渲染进程无 Node 权限
- 所有 IPC 通过 `contextBridge.exposeInMainWorld` 暴露

### 4.7 关键交互逻辑

**截图流程**:
1. 注册快捷键 Ctrl+Alt+Z
2. 用户按下快捷键 → 隐藏所有便利贴窗口
3. 等待 80ms → 使用 desktopCapturer 捕获屏幕
4. 显示截图覆盖层 → 用户框选区域
5. 用户确认选区 → 裁剪图片 → 保存到 images 目录
6. 创建新便利贴（或添加到当前便利贴）→ 恢复显示便利贴

**堆叠合并检测**:
- 拖拽结束 300ms 后检测
- 计算两个堆的位置差值
- 若 x 和 y 方向距离均小于阈值(30px)，且合并后总数≤3，则合并

**翻页动画**:
- 使用 CSS 3D perspective + rotateY
- perspective: 1200px
- 动画时长: 500ms, ease-in-out
- 翻出角度: rotateY(-110deg)
- 翻入角度: rotateY(90deg) → rotateY(0deg)

**日报生成流程**:
1. 用户点击工具栏"日报"按钮
2. 自动收集所有今天修改过的便利贴内容
3. 提取纯文本（包括待办事项状态）
4. 调用 DeepSeek API 进行工作内容筛选和结构化整理
5. 生成包含"今日完成"、"进行中"、"问题风险"、"明日计划"的日报
6. 保存到历史记录（reportHistory）中

**日报配置项**:
- `deepseekApiKey`: DeepSeek API 密钥（可选，不配置则使用本地兜底逻辑）
- `dailyReportModel`: 使用的模型，默认 `deepseek-v4-flash`
- `dailyReportWorkContent`: 用户工作内容描述，用于 AI 筛选

**日报数据结构**:
```json
{
  "id": "UUID",
  "title": "5月10日日报",
  "content": "HTML格式的日报内容",
  "rawText": "纯文本格式的日报",
  "createdAt": "ISO8601"
}
```

## 5. Testing Decisions

### 5.1 测试策略

- **端到端测试**: 使用 Electron 内置测试框架
- **手动测试清单**: 覆盖所有用户故事
- **边界测试**: 堆叠限制(3张)、窗口边界、多显示器

### 5.2 关键测试场景

1. 创建、编辑、删除便利贴的数据持久化
2. 拖拽合并与拆分功能
3. 翻页动画流畅性
4. 截图快捷键响应
5. 窗口边界限制
6. JSON 数据损坏恢复
7. 多显示器截图
8. 日报生成功能（点击日报按钮）
9. 日报历史记录保存与恢复
10. DeepSeek API 配置与调用

### 5.3 现有测试

项目包含 `test-electron.js` 用于基本功能验证。

## 6. Out of Scope

以下功能当前版本不包含：

- 云同步或跨设备同步
- 便利贴颜色自定义
- 多人协作
- 便利贴标签或分类
- 提醒或定时功能
- 导出为 PDF/图片
- Mac/Linux 版本
- 国际化（i18n）
